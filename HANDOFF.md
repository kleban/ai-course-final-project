## Що це

Data Story — локальний аналітичний MVP для фінального проєкту курсу AI Agents for Developers. Python 3.13, NiceGUI + FastAPI в одному процесі, SQLite, pandas. Один Windows-комп’ютер, без входу. Інтерфейс український; дашборд у стилі дашборда автора, логотип автора, акцент `#174690`.

## Як запустити й перевірити (Windows, подвійний клік)

1. `Setup.cmd` — один раз і після змін `requirements.lock` (потрібен інтернет).
2. `Check.cmd` — pip check, ruff, формат, mypy, 50 автотестів.
3. `Start.cmd` → http://127.0.0.1:8765; `Stop.cmd` — зупинка.
4. Демо-дані: `samples/demo_apartments.csv`, `.xlsx` (синтетичні).
5. Для розробника — UI-смоук через Playwright (34 сценарії; Playwright не входить у `requirements.lock`):
   `python tools/start.py --no-browser --port 8899 --database tmp/smoke/data.sqlite3`, потім `python tools/ui_smoke.py http://127.0.0.1:8899`.

## Карта коду

- `src/data_story/` — `storage.py` (SQLite, міграції, схема v4), `projects.py`, `project_types.py` + `instructions/*.md`, `configuration.py`, `datasets.py`, `metadata.py`, `contracts.py`, `service.py` (спільний для UI та API), `web.py`, `screen.py` (усі екрани), `markdown_editor.py` + `assets/markdown_editor.js` (редактор), `icons.py` → `assets/icons.css` (іконки додавати лише тут), `assets/` (стиль, шрифти, логотип, `vendor/toastui/`).
- `tests/` — 50 тестів; `tools/` — запуск, перевірки, демо-дані, UI-смоук, генератор аркуша іконок.
- `planning/` — план, статус, рішення, специфікації, архітектура.
- `design/logo/final/` — фінальний логотип (інші чернетки логотипа застарілі); `design/reviews/` — знімки ітерацій.
- `runtime/` (не в Git) — робоча БД, файли наборів, стан інтерфейсу.

## Що робити далі

1. Отримати від автора: ручний огляд редактора, приймання 02/02b, відгук щодо дизайну, підтвердження D-25 і справжній демонстраційний набір.
2. Правки за відгуком.
3. Лише після окремої згоди — етап 03 «Статистика»: специфікація → описові показники, пропуски, кореляційна матриця, контрольні розрахунки без AI з урахуванням метаданих 02b. Далі за [`planning/plan.md`](planning/plan.md).

## Відкриті рішення автора

- Формати й ліміт завантаження (D-25), справжній демонстраційний набір.
- Моделі OpenAI й спосіб зберігання ключа (етап 08, `planning/ai-settings.md`).
- Формати звітів і вибір Quarto (етап 10).
- Вимоги курсу до здачі ще не підтверджені.

## Як працювати й фіксувати

- Один компонент → перевірка → фіксація → наступний (D-15). Усе в цьому репозиторії, без CDN (D-36).
- Після ітерації: новий запис у `PROJECT_HISTORY.md` (наступний номер — **035**), оновити `planning/status.md`, `planning/plan.md`, `planning/decisions.md`, README за потреби, цей файл; коміт. Пуш — лише за дозволом автора.
- Поточні файли передачі описують стан, а не хронологію: замінювати застарілі абзаци, а не дописувати нові в кінець.
- Автор часто працює з телефона: тоді без керування комп’ютером і браузером. Автотести, mypy і UI-смоук можна запускати в хмарному середовищі, скопіювавши чисті Python-пакети з `.venv` автора.
- Git: гілка `main`, remote `origin` — `https://github.com/kleban/ai-course-final-project.git`. Стан перевіряти через `git status -sb`.
