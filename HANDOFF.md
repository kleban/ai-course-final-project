# Data Story — почати тут (передача роботи)

Оновлено: 2026-10-10 (Europe/Kiev), після історії 033. Цей файл — коротка точка входу для нового агента чи нового діалогу. Деталі — у `planning/status.md` (розділ «Як продовжити роботу») і `PROJECT_HISTORY.md`. Правила роботи — `AGENTS.md`, їх треба прочитати й дотримуватися.

## Що це

Data Story — локальний аналітичний MVP для фінального проєкту курсу AI Agents for Developers. Python 3.13, NiceGUI + FastAPI в одному процесі, SQLite, pandas. Працює на одному Windows-комп'ютері, без входу. Інтерфейс український, дизайн — дашборд у стилі дашборда автора, логотип автора.

## Як запустити й перевірити (Windows, двічі клацнути)

1. `Setup.cmd` — один раз і після змін `requirements.lock` (потрібен інтернет).
2. `Check.cmd` — ruff, формат, mypy, 50 автотестів.
3. `Start.cmd` → браузер http://127.0.0.1:8765; `Stop.cmd` — зупинка.
4. Демо-дані для ручної перевірки: `samples/demo_apartments.csv`, `.xlsx`.
5. Необов'язково, для розробника: UI-смоук через Playwright (34 сценарії):
   `python tools/start.py --no-browser --port 8899 --database tmp/smoke/data.sqlite3`, потім `python tools/ui_smoke.py http://127.0.0.1:8899`. Playwright не входить у `requirements.lock`.

## Карта коду

- `src/data_story/` — `storage.py` (SQLite, міграції, схема v4), `projects.py`, `project_types.py` + `instructions/*.md`, `configuration.py`, `datasets.py`, `metadata.py`, `contracts.py` (Pydantic), `service.py` (єдиний сервіс для UI та API), `web.py` (API, сторінки), `screen.py` (усі екрани), `icons.py` → `assets/icons.css`, `assets/` (стиль, шрифти Plex/STIX, логотип).
- `tests/` — 50 тестів; `tools/` — запуск, перевірки, генератор демо-даних, UI-смоук.
- `planning/` — план, статус, рішення, специфікації (`subsystem-01-projects.md`, `subsystem-02-datasets.md`, `metadata-proposal.md`, `ai-settings.md`).
- `design/logo/final/` — фінальний логотип і всі похідні (`design/logo/*` поза `final/` — застарілі чернетки).
- `runtime/` (не в Git) — робоча БД, файли наборів, стан інтерфейсу.

## З чого почати в новому діалозі

1. Прочитати `AGENTS.md`, потім розділ «Як продовжити роботу» в `planning/status.md`.
2. Автор вручну перевіряє TOAST UI Editor: `Start.cmd` → «Типи проєктів», форматування, підказки, перегляд, збереження й відновлення типової інструкції. Редактор уже інтегровано; Setup не потрібен, Python-залежності застосунку не змінено. Потім отримати відгук щодо дизайну й приймання 02/02b.
3. Наступна робота (лише після згоди автора): **етап 03 «Статистика»** — описові показники, пропуски, кореляційна матриця (теплова карта) для числових стовпців набору; контрольні розрахунки без AI; враховувати типи й ролі з метаданих 02b. Далі за `planning/plan.md`: 04 графіки й формули (MathJax), 05 підготовка/зведення (DuckDB для з’єднань і агрегацій, ще не реалізовано), 06 регресія, 07 RAG, 08 налаштування й адаптер OpenAI (+ LLM-перетворення опису в метадані), 09 агент, 10 генерація звітів (Quarto — кандидат), 11 підсумок і демонстрація.

## Відкриті рішення автора

- Підтвердити формати й ліміт завантаження (D-25: CSV UTF-8/Windows-1251, XLSX перший аркуш, 20 МБ).
- Справжній демонстраційний набір даних (зараз синтетичний).
- Конкретні моделі OpenAI й спосіб зберігання ключа (етап 08, `planning/ai-settings.md`).
- Вимоги курсу до здачі ще не підтверджені.
