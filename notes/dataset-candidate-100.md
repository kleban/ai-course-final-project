# Пошук цікавого набору для презентації

Уточнення 101: автор погодив Seoul; перша задача 2026-10-13 — демонстраційні графіки. Нижче — первинний добір 100.

2026-10-12, історія 100. Автор попросив знайти цікаву альтернативу Melbourne. Це пропозиції агента; основний демонстраційний набір автора не замінювався.

## Рекомендація: місто, погода й попит на велосипеди

[Seoul Bike Sharing Demand, UCI](https://archive.ics.uci.edu/dataset/560/seoul+bike+sharing+demand). Зрозуміла історія для різної аудиторії: коли людям потрібні велосипеди, як відрізняються сезони/свята/погода, що здатна пояснити модель. Підходить для графіків, зведень DuckDB, категоріальних ознак і регресії. CSV невеликий, без реєстрації; ліцензія CC BY 4.0 із зазначенням джерела.

Завантажено офіційний архів; оригінал збережено. Для сервісу підготовлено samples/seoul_bike.csv (тільки перекодування Latin-1→UTF-8). Штатний читач/профіль підтвердив 8760×14, 604168 байтів, пропусків 0, повних дублікатів 0, період 2017-12-01—2018-11-30. Опис полів — samples/seoul_bike.description.md; повні перевірки/хеші — dataset-candidate-100-verification.json.

## Вже перевірений сюжет

На рядках Functioning Day=Yes середній погодинний попит найбільший о 18:00 — **1554,02** прокатів; далі 19:00 — 1235,78 і 17:00 — 1177,21. Це власний описовий розрахунок на завантаженому CSV, не число зі сторонньої статті й не результат AI. Гіпотеза про вечірні поїздки після роботи — лише можлива інтерпретація, не підтверджена причина.

Можливі питання презентації: чи завжди тепліший день означає більший попит; наскільки відрізняються дощові години; які години навантаження треба враховувати оператору? Відповіді поки не стверджуються: їх треба обчислити із сезонними/годинними відмінностями. 295 годин закритої системи показують корисний приклад перевірки контексту даних. При демонстрації моделі відділяти прогноз попиту відкритого прокату від факту його роботи.

## Межі виконаної роботи й наступний крок
