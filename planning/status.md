# Поточний стан

Оновлено: 2026-10-10 (Europe/Kiev), історія 025.

Виконано: збережено задум і історію; визначено основне джерело графіків; знайдено й прочитано теми Python та R; автор підтвердив RAG; створено [специфікацію 0.3](specification.md) і перелік відповідності потребам автора.

Поточне завдання: обговорити [архітектуру 0.3](architecture.md) і специфікацію 0.3. Підтверджено локальний Python MVP, зовнішній OpenAI, простий UI й трасування. Після уточнень запропоновано NiceGUI + FastAPI, SQLite, pandas, NumPy, statsmodels, Plotly, MathJax та RAG; бібліотеки й модель не затверджені. Автор запропонував назву Data Story.

Наступні кроки: погодити UI й серверну схему; визначити модель і спосіб доступу до OpenAI; отримати дані та вибрати питання; підтвердити формати, роль БД, склад RAG і політику trace; довивчити потрібні правила графіків та вимоги курсу. Окремо обрати назву.

Прогалини: немає наданих демонстраційних даних, остаточного обсягу й підтверджених умов здачі. Вони не блокують підготовку документа, але обмежують готовність до реалізації.

Перевірки: документ звірено з доступними записами задуму; функції мають статус і критерії приймання. Код сервісу не створено; теми не запускалися; тести застосунку не виконувалися.

Уточнення 013: документовано F-16 (налаштування ключа та моделей) і F-17 (фактичні токени без вартості), додано [ai-settings.md](ai-settings.md). Потрібно погодити системне сховище ключа як вузький виняток; моделей у конкретному акаунті не перевірено. Документацію перевірено на структуру та локальні посилання; API-запитів і запису секретів не виконували.

Обговорення 014: рекомендовано локальний пошук RAG для уникнення API-платежів за embeddings/пошук. Потрібно обрати й перевірити багатомовну модель, CPU-продуктивність та якість пошуку; рішення ще не затверджено. Зовнішня генерація OpenAI лишається платною. Жодних залежностей чи ваг не встановлювали.

## Ітерація 017 — екран проєктів і запуск; етап 01 завершено

Реалізовано: NiceGUI + FastAPI в одному процесі (`web.py`), спільний сервіс і контракти (`service.py`, `contracts.py`, `validation.py`), HTTP API `/api/projects…`, `/health`, `/shutdown`; `Setup.cmd`, `Start.cmd`, `Stop.cmd`, `Check.cmd`, `tools/start.py`, `tools/check.py`; стиль і шрифти лекції в `assets/`.

Перевірено 2026-10-10 на Windows автора:

- `Check.cmd`: pip check, ruff, формат, mypy і 21 автоматичний тест — успішно.
- `Start.cmd`: сервер на 127.0.0.1:8765, браузер відкрився, порожній список.
- Браузер: створено два проєкти з однаковою українською назвою — різні ID; порожня назва дає «Назва: введіть значення.» без запису; відкриття показує поточний проєкт і журнал.
- Повторний `Start.cmd` під час роботи: другий сервер не створено, лише відкрито браузер.
- `Stop.cmd`: сервер завершився, вікно запуску закрилося, `/health` недоступний.
- Повторний `Start.cmd` після зупинки: обидва проєкти на місці; журнал показує створення й нові відкриття.

Обмеження й зауваження: `runtime/application.log` порожній — події проєктів пишуться в журнал SQLite, а файловий лог поки фіксує лише помилки сервісу; у робочій БД лишилися два тестові проєкти «Тест перезапуску — Київ» (видалення в MVP не передбачено; за потреби можна видалити файл `runtime/data-story.sqlite3` при зупиненому сервері). Сценарій «порт зайнятий чужою програмою» перевірено автотестом, не вручну. Git-коміту ще немає: усі файли не відстежені.
