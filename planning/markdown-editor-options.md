# Markdown-редактор для конфігурації — варіанти

Оновлено: 2026-10-10 (Europe/Kiev), історія 028. Автор вибрав TOAST UI Editor; інтеграцію завершено. Порівняння нижче — історія вибору (026–027), не поточна невизначеність.

У `settings_screen` textarea замінено власним компонентом `MarkdownEditor`; Markdown зберігається через той самий `service.save_instruction`. Кнопки збереження/відновлення й серверна валідація збережені.

| --- | --- | --- |
| TOAST UI Editor | Markdown з переглядом і перемикання на візуальне редагування; таблиці, панель форматування, українська локалізація | [Демо](https://nhn.github.io/tui.editor/latest/tutorial-example01-editor-basic/), [офіційний опис](https://ui.toast.com/tui-editor/) |

Рекомендація агента — TOAST UI Editor: перемикання між розміткою й візуальним режимом, зручність для нетехнічного користувача, українська локалізація. EasyMDE — другий варіант, якщо пріоритетом є редагування точного Markdown-тексту. Milkdown варто порівняти за відчуттям візуального введення; інтеграція потребуватиме власного компонента й підготовки JavaScript-ресурсів.

Перевірено офіційні описи та місце інтеграції в нашому коді; жоден кандидат поки не встановлений і не протестований у NiceGUI. Це бібліотеки інтерфейсу, не глобальні плагіни Codex. Ліцензії та склад ресурсів остаточно перевірити для обраної версії.

Пропозиція критеріїв інтеграції: локальні ресурси в репозиторії, без залежності від CDN під час роботи; стиль Data Story й власні іконки; українські написи; збереження Markdown без втрат після перезапуску; блоки коду, списки, таблиці; відновлення типової інструкції, ліміт 20000 символів, повідомлення помилок. Перевірити семантичні зміни при перемиканні візуального режиму, щоб промпт не змінювався непомітно. MathJax залишається окремим майбутнім компонентом — вибір редактора не замінює рішення D-12.

Відкрите рішення: автор вибирає редактор; коміт і пуш — після інтеграції та перевірок за його останнім уточненням.

## Уточнення автора — історія 027

Підказки під час редагування — важливий критерій; постійний перегляд зараз не потрібний, але може бути корисним для майбутніх звітів. Пропозиція агента: пояснення кнопок і синтаксису українською, вставлення шаблонів заголовків/списків/таблиць/коду, за потреби автодоповнення. Це локальна допомога без AI-викликів. Звичайні tooltip і власне автодоповнення — різні можливості; готове автодоповнення Markdown у кандидатів ще не підтверджено.

Редагування точного Markdown залишається головним; перегляд пропонується вмикати за кнопкою. Для майбутнього Quarto звичайний Markdown-редактор не гарантує підтримки всього `.qmd` (YAML, посилання на рисунки, спеціальні блоки). Пропонується генерувати службову оболонку `.qmd` окремо, а користувачу редагувати текст звіту. Це не потребує зараз інтегрувати повноцінний редактор Quarto. Бібліотека ще не обрана.

## Реалізація — історія 028

TOAST UI Editor 3.2.2, основний і єдиний доступний режим редагування — Markdown. Панель Data Story має українські пояснення й коротку довідку; це локальна допомога, автодоповнення або AI-підказки не реалізовані. Перегляд вмикається за кнопкою; ліміт має лічильник і серверну відмову. Збереження читає актуальний текст безпосередньо з браузерного компонента при натисканні, не покладається на відкладене передавання останнього символу. Відновлення типової інструкції користується наявним сервісом.

Локальні JS/CSS/українська локалізація й ліцензія в `assets/vendor/toastui/`; походження та SHA-256 в його README. Usage tracking вимкнено. Візуальне редагування приховано, щоб не перетворювати інструкції між Markdown і WYSIWYG. Перевірено 28 UI-сценаріїв, включно з точним збереженням розмітки, довідкою, переглядом, шаблоном таблиці/скасуванням, валідацією, відновленням і мобільною шириною; зовнішніх запитів не було. Ручний огляд автора попереду. Знімки — `design/reviews/028-markdown/`.
