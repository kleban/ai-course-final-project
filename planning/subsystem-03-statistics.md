# Етап 03 — Статистика

Редакція 0.1, 2026-10-10 (Europe/Kiev), історія 044. **Пропозиція агента на погодження; код не написано.** D-54 дозволяє підготувати специфікацію, але не реалізувати її до відповіді автора. Це критерії нашого MVP, а не встановлені вимоги курсу.

## Мета й підстави

Дати аналітику короткий перевірюваний огляд одного набору: описові показники, пропуски та числову кореляційну матрицю для майбутньої теплової карти. Усі розрахунки локальні, без AI, на всіх рядках набору.

Підстави: D-11, D-26, D-43–D-45, D-48 і D-54 у [decisions.md](decisions.md); порядок 03 → 04 → 05 → 06 у [plan.md](plan.md). Чинні типи й ролі — `Kind`, `Role`, `ColumnMeta`, `MetadataStore` у [metadata.py](../src/data_story/metadata.py), розпізнавання дат — `detect_dates`, `DATE_FORMATS`, профіль у [datasets.py](../src/data_story/datasets.py). Походження Melbourne — [опис набору](../samples/melb_data.description.md). Загальний задум 02b — [metadata-proposal.md](metadata-proposal.md); у разі розбіжностей контрактом є поточна реалізація, а не початкова пропозиція.

## Сценарій

1. У відкритому проєкті користувач переходить до «Статистика» й обирає один із його наборів; назви проєкту й набору завжди видимі. Без наборів — пояснення й наявна кнопка «Завантажити дані».
2. Обирає один перегляд: «Описові показники», «Пропуски» або «Кореляції». На екрані одна компактна таблиця з підписами й коротким поясненням методу; довгі таблиці — посторінково (D-48), до браузера надходить потрібна сторінка.
3. Бачить стан метаданих, фактичну кількість рядків і використані поля. Для кореляцій може звузити вибір серед придатних числових полів; причини виключення решти показано.
4. Після збереження метаданих і повторного відкриття/оновлення розрахунок використовує їхню нову версію. Фільтри й сторінка таблиці даних етапу 02 не впливають на статистику; підпис «Увесь набір» робить це явним.

## Дані й метадані

- Джерело значень — збережений CSV, прочитаний за правилами 02; `observed`, описи, одиниці й очікувані діапазони не підміняють дані. Статистика не змінює оригінал, профіль чи метадані.
- Використовуємо останні **збережені** метадані, включно з чернеткою, з видимим попередженням «Метадані не підтверджено». Без збереженого документа — скелет 02b з даних і таке саме попередження. Незбережені зміни форми не враховуються. Підтвердження не потрібне для відкриття статистики.
- Показуємо `label` разом із вихідним `name`, `unit`, тип і роль. Ролі `feature` і `target` допускають аналіз за типом; цільову змінну виділяємо підписом, але не вимагаємо її вибору чи єдиності для статистики. Роль `id` або `ignore`, а також тип `id` виключають поле з числових показників і кореляцій; у загальному огляді пропусків воно лишається з позначкою ролі.
- Тип метаданих визначає зміст аналізу, а фактичні значення — можливість розрахунку. Наприклад, числовий `Postcode`, позначений категорією, має категоріальний огляд і не має середнього чи кореляцій. Числові категорії не кодуємо як порядкові числа; `bool` не включаємо до кореляцій.
- Для типу `number` потрібне фактичне числове поле; для типу `date` — дата, розпізнана правилами 02. Суперечність показуємо для конкретного поля й не обчислюємо його спеціальні показники; пропуски та придатні інші поля залишаються доступні. Без довільного перетворення текстів у числа або повторного вгадування формату дат.
- Дати використовують розпізнаний `date_format` із профілю, а не числовий час чи текстовий порядок. Для неоднозначного формату повторюємо попередження 02 й указуємо обраний формат. Не створюємо з дат рік/місяць як нові ознаки; це етап 05.
- Базові пропуски — значення, які чинний парсер 02 прочитав як відсутні. Додаткові `missing_codes` зі збережених метаданих застосовуємо лише в розрахунковому представленні: для числового поля — точна числова рівність із числовим кодом, для решти — точний текст після обрізання крайніх пробілів, без зміни регістру. Непридатний числовий код — помилка правила цього поля, без мовчазного ігнорування. Коди не вгадуємо: нуль є значенням, якщо його явно не вказано кодом пропуску.
- Очікуваний діапазон і перелік категорій дають попередження 02b, але не відкидають спостереження. Нескінченні числа рахуються окремо як непридатні; не підміняємо їх пропусками й не використовуємо в числових формулах.

## Результати й правила обчислення

| Перегляд | Мінімальний результат |
| --- | --- |
| Описові: число | Кількість придатних значень, середнє, вибіркове стандартне відхилення, мінімум, Q1, медіана, Q3, максимум |
| Описові: категорія / текст / так-ні | Кількість заповнених, кількість унікальних, найчастіше значення й його частота; при рівних частотах — перше за текстовим порядком і позначка про рівність |
| Описові: дата | Кількість заповнених, кількість унікальних дат/моментів, найраніша й найпізніша дата; показ часу, якщо він є у форматі |
| Пропуски: усі поля | Усього рядків N; базові пропуски; додаткові за кодами (без подвійного рахунку); їхня сума й частка 100 × сума / N; окремо кількість непридатних нескінченних чисел |
| Пропуски: набір | Кількість і частка рядків хоча б з одним пропуском серед усіх полів; поля `id` / `ignore` також у цьому підсумку |
| Кореляції | Симетрична матриця Pearson r та відповідна матриця кількості спільних придатних спостережень n; вихідні назви полів і доступні людські підписи |

Стандартне відхилення — з дільником n−1; при n<2 показуємо «—» з причиною. Квартилі — лінійна інтерполяція позиції (n−1)×p у впорядкованих значеннях, p=0,25/0,5/0,75. Порожнє поле не має мінімуму, середнього, моди чи діапазону. При N=0 частка не визначена, а не 0%.

Кореляції: тип `number`, роль `feature` / `target`, без `id` / `ignore`. Пропуски й непридатні числа вилучаються **попарно**, тому n може відрізнятися для різних клітинок. Для n<3 або нульової варіації хоча б одного поля — «—» із причиною, включно з діагоналлю; інакше діагональ 1. Обчислення з повною точністю, округлення лише при показі: числа до 3 десяткових знаків, r до 3, частки до 2; кількості — цілі. Кореляція описує лінійний зв’язок і не доводить причинності; повідомлення також пояснює попарне вилучення та показує n для обраної пари.

## Межі й помилки

У 03 — таблиці та розрахункові матриці; малювання теплової карти, тема графіків і MathJax — етап 04. Тут немає регресії, перевірки гіпотез, групувань, заповнення пропусків, видалення викидів, з’єднань, AI-пояснень, експорту чи нових залежностей. Повторне відкриття відтворює результат із файла й метаданих; постійне сховище аналітичних результатів для звітів не додаємо в цьому етапі.

Набір не обрано, немає придатних числових полів або обрано менше двох — пояснення замість порожньої матриці. Порожнє/стале поле, недостатньо пар, розбіжність типу чи помилка коду пропуску — стан конкретного поля/пари, решта результатів доступна. Відсутній набір, належність іншому проєкту, відсутній/пошкоджений файл — відмова всьому запиту з коротким українським повідомленням; часткового успішного результату немає.

Одна дія розрахунку — одна подія журналу проєкту: набір, вид розрахунку, поля, SHA-256 файла, стан і `updated_at` метаданих, метод, кількість рядків, тривалість, успіх/помилка. Сирі рядки й секрети не записуємо. Результат у пам’яті, якщо кешуватиметься, залежить від файла, метаданих і параметрів; зміна метаданих не може повернути старі числа.

## Контроль без AI й критерії приймання

Нижче — **план перевірок після погодження**, а не вже виконані розрахунки етапу 03. Базові контрольні факти наведено з `samples/README.md`, історії 036 і тесту Melbourne у `tests/test_datasets.py`; застарілий запис README про текстовий тип `Date` не використовуємо — чинний профіль розпізнає дату (D-45).

1. На незміненому `samples/melb_data.csv` (SHA-256 із опису джерела) перевірити 13 580 × 21; без додаткових кодів пропуски: `BuildingArea` 6 450, `YearBuilt` 5 375, `CouncilArea` 1 369, `Car` 62, решта 0. Частки перевірити діленням на 13 580, а не на кількість заповнених. Рядки з пропусками порахувати об’єднанням ознак рядків, а не сумою пропусків стовпців.
2. Для `Price`, `Rooms`, `BuildingArea` і пари `Price`–`Rooms` підготувати незалежний контроль: окреме читання CSV, явні суми для середнього, відхилення й Pearson, сортування для квартилів, підрахунок спільних пар. Контроль не викликає майбутній модуль статистики; значення та спосіб отримання зафіксувати в репозиторії під час реалізації. Цілі кількості збігаються точно, дійсні — з абсолютним або відносним допуском 10⁻⁹ до округлення.
3. `Date`: 28.01.2016–23.09.2017, формат ДД/ММ/РРРР; не входить у Pearson. У тестовій копії метаданих `Postcode=category`, `Price=target`, одне числове поле з роллю `ignore`, інше з `id`: виключення правильні, ціль лишається придатною; оригінальні метадані демо-проєкту не змінювати.
4. На малих контрольних наборах перевірити n=0/1/2, повністю порожнє й стале поле, рівні частоти, нескінченність, попарні пропуски, явний код пропуску й звичайний нуль, чернетку/підтвердження, помилку типу, дату з часом та неоднозначну дату. Усі нечислові результати формул передаються як відсутні з причиною, без NaN/Infinity у відповіді.
5. Перевірити ізоляцію двох проєктів і незалежної копії 02c, повторне відкриття після перезапуску, перерахунок після зміни метаданих, журнал успіху/помилки. UI-сценарій Melbourne: вибір набору → три окремі перегляди → зміна метаданих → оновлені результати; без зовнішніх запитів. Після реалізації — потрібні автоперевірки та ручне приймання автора.

**Наступний крок:** погодження автором цієї редакції; до відповіді код етапу 03 не писати.
