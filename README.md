# Data Story — локальний аналітичний MVP

Оновлено: 2026-10-14, історія 131. Опис для читачів — https://kleban.github.io/ai-course-final-project/ (`docs/`). Для продовження розробки почніть із [HANDOFF.md](HANDOFF.md).

Data Story допомагає пройти шлях від набору CSV до аналізу, лінійної регресії, висновків і HTML-звіту. Сервіс працює на одному комп'ютері Windows, без входу й облікових записів.

## Що працює

- Проєкти, CSV до 5 МБ, таблиця даних, метадані та незалежні копії наборів.
- Описова статистика, пропуски, кореляції; гістограма, розсіювання, теплова карта та графік пропусків. Теми графіків і MathJax локальні.
- Підготовка даних, заповнення ознак, кодування категорій і поділ на вибірки. Перетворення навчаються лише на навчальній частині. Типовий поділ — 70/30.
- Лінійна регресія: коефіцієнти, стандартні помилки, p-value, тестові R²/MAE/RMSE, порівняння з простим прогнозом і графіки перевірки.
- Агрегація й з'єднання в DuckDB: у конструкторі SQL складає сервіс; у чаті LLM пропонує один SELECT, який сервіс виконує в ізольованій DuckDB (лише таблиці проєкту, 5 с, 512 МБ, до 10 000 рядків). Результат показується для перегляду й стає новим набором лише після «Застосувати».
- База знань: редаговані правила й перевірені уривки книжок (індекс 106 уривків); локальний bge-m3 + TF-IDF. Якщо embeddings недоступні або обчислення завершилось помилкою, працює TF-IDF правил із поясненням причини; книжковий пошук потребує embeddings.
- AI-помічник: «Порадь», «Виконай», «Поясни результат», уточнення, чернетки опису й метаданих, графіки за текстовою командою. Зміни чернеток застосовує користувач.
- Висновки з фактів і джерел: редагування та явне затвердження. Звіти: редагована чернетка, окрема дія AI, локальний Quarto → HTML; перегляд A4, версії, HTML/.qmd/ZIP.
- Налаштування моделей за задачами (gpt-6-luna, gpt-6.1-sol; до 3 рівнів і повтори), журнал запитів/відповідей/помилок, фактичні токени й вартість у доларах за тарифами, які задаються на сторінці «Моделі AI» (D-106).

Голосового введення, класифікації, кластеризації, PDF/DOCX-звітів, Q-Q/VIF/відстані Кука та крос-валідації в поточному MVP немає. Критерії здачі курсу ще не підтверджені.

## Відомі обмеження

- **Один користувач, один процес.** Немає входу, облікових записів і ролей; сервер слухає лише 127.0.0.1. Не запускайте демонстраційні генератори одночасно із сервером на тій самій базі.
- **OpenAI — зовнішній сервіс.** AI-функції потребують ключа й інтернету; дані, які користувач надсилає явною дією (фрагменти таблиць, метрики, уривки бази знань), ідуть до OpenAI. Без ключа працюють усі локальні розрахунки.
- **Вартість — оцінка.** Рахується з фактичних токенів відповіді та тарифів, введених у «Моделі AI»; це не рахунок OpenAI. Для промптів понад 272 тис. токенів, без токенів або без тарифу — «невідомо».
- **Модель.** Лише лінійна регресія з випадковим поділом 70/30: показує зв'язки в даних, а не перевіряє прогноз майбутнього для часових рядів.
- **Розмір даних.** CSV до 5 МБ; SQL від LLM — до 10 000 рядків і 2 МБ результату.
- **База знань.** Пошук перевірено на контрольних, перефразованих і сторонніх питаннях (`tools/knowledge_eval.py`), але розмовні формулювання можуть не знайти правило; без bge-m3 працює лише TF-IDF правил.
- **AI-тексти — чернетки.** Висновки й пояснення AI потребують перевірки та явного затвердження; до звіту потрапляє лише затверджене.
- **Не перевірено:** чисте встановлення на іншому ПК, ручне відкриття презентації в PowerPoint.

## Запуск Windows

Потрібен Python 3.13 із Windows Python Launcher.

1. Один раз і після зміни залежностей — `Setup.cmd`: локальне середовище, пакети, портативний Quarto й bge-m3 (~2,3 ГБ). Первинне встановлення потребує інтернету.
2. Щодня — `Start.cmd`: сервер і браузер на http://127.0.0.1:8765. Вікно запуску залишайте відкритим.
3. Зупинка — `Stop.cmd` або закриття вікна запуску. Повторний запуск відкриває наявний сервіс; чужий процес на зайнятому порту не зупиняється.

Дані: `runtime/data-story.sqlite3`, схема v16; файли — `runtime/projects/`. Схема оновлюється під час запуску. Сервер слухає лише 127.0.0.1. Дані, залежності й тимчасові файли виключені з Git.

OpenAI: скопіюйте `.env.example` у `.env` та задайте `OPENAI_API_KEY`. Не додавайте ключ до Git або описів. Виберіть моделі в «Налаштування → Моделі AI». Генерація — лише явною дією; без ключа працюють локальні розрахунки. Щоденна робота не залежить від CDN.

## Перевірки й межі

`Check.cmd` — залежності, правила/формат коду, типи та повний набір офлайн-тестів. `Check-Projects.cmd` — лише тести. Автотести ізольовані від великої ONNX-моделі: використовують TF-IDF та імітації embeddings/OpenAI; це не перевірка реальної генерації. Реальний embeddings-пошук перевіряє `tools/windows/Check-Embeddings.cmd`. Браузерні сценарії окремі (`tools/*_ui_smoke.py`); останній повний прохід — [notes/demo-check-119.md](notes/demo-check-119.md).

Історично: ітерація 099 виправляє зауваження [ревю 098](notes/project-review-098.md); результат перевірок і актуальні межі — [notes/fixes-review-099.md](notes/fixes-review-099.md). Для моделей попереднього методу статистика значущості прихована з поясненням; нові p-value потребують нових вибірок (з іншим зерном) і навчання. Збережені авторські висновки й старі знімки звітів автоматично не переписуються.
